# Custom kernels

A Metalium program (a reader, a compute and a writer kernel, with their circular buffers
and arguments) becomes a torch op on tt tensors, from Python or from C++. It runs on the
default stream in order with every other op, and on a mesh on every chip. Runnable
examples of all three forms, and when to pick which: [examples/kernels](../../examples/kernels/README.md).

## From Python

[examples/kernels/metalium](../../examples/kernels/metalium/):

```python
import kohakutt.kernels as kk


@kk.op("myns::swiglu(Tensor a, Tensor b) -> Tensor")
def swiglu(a, b):
    out = kk.empty_like(a)
    split = kk.split_tiles(a)
    return kk.Program(
        cbs=[kk.CB(0, a), kk.CB(1, b), kk.CB(16, out)],
        reader=kk.Kernel("kernels/reader.cpp", [a, b], lambda c: [a, b, *split[c]]),
        compute=kk.Kernel(
            "kernels/compute.cpp", runtime_args=lambda c: [split[c][1]], fp32_dest=True
        ),
        writer=kk.Kernel("kernels/writer.cpp", [out], lambda c: [out, *split[c]]),
        outputs=[out],
        cores=split,
    )


y = torch.ops.myns.swiglu(a_tt, b_tt)
```

A tensor in a kernel's compile-time arguments becomes its `TensorAccessorArgs`, in its
runtime arguments its buffer address. The description is built once per argument sizes
and dtypes; later calls only patch buffer addresses. `examples/kernels/metalium/rope.py` is
a second program in the same form whose compute kernel is written in SFPU instructions
(bf16 input, fp32 table, bf16 output).

## From Python, generated

[examples/kernels/dsl_metal](../../examples/kernels/dsl_metal/): `kohakutt.dsl.metal`
describes the same program (buffers, the three kernels, their arguments) in Python,
checks it against the hardware's rules and writes the kernel sources. Sizes are runtime
arguments, so a new batch or length compiles nothing. See [the kernel DSL](../concepts/dsl.md).

**Writing an input in place.** An argument the op's schema marks `Tensor(a!)` (as in
`gdn_decode_km(Tensor(a!) state, ...)`) is handed to the program as its own storage,
not a copy, so the program may write it. It must be a whole contiguous bf16, fp32 or
int32 tensor (else the call raises). The write counts as any in-place op's: the first
one outside traces moves the storage to a private buffer (a buffer it shared with
another tensor keeps its values), its version counter and the backend's write epoch
advance, a capture's replays record it, and `torch.compile` (`ktt_tt`) keeps the
tensor in place in its traces.

## From C++

[examples/kernels/cpp_extension](../../examples/kernels/cpp_extension/): the program
builder includes `ktt/extension/device.hpp` (TT-NN side), the op includes
`ktt/extension/torch.hpp` (torch side), and `kohakutt_add_extension()` from the
installed package's CMake module builds the library:

```cpp
// device side
// tensors: the inputs, then the outputs; numerics: the caller's scope
ProgramDescriptor swiglu(
    const std::vector<ttnn::Tensor>& tensors, const ktt::extension::Numerics& numerics
);
KTT_REGISTER_PROGRAM("myns::swiglu", swiglu);

// torch side
at::Tensor swiglu_op(const at::Tensor& a, const at::Tensor& b) {
    return ktt::extension::run(
        "myns::swiglu", {a, b}, {{a.sizes().vec(), a.scalar_type()}}
    )[0];
}
```

```python
import kohakutt.extension

kohakutt.extension.load("build/swiglu_ext/swiglu_ext.so")
y = torch.ops.myns.swiglu(a_tt, b_tt)
```

## API

| API | Does |
|---|---|
| `kk.op(schema)` | registers a Python program builder as a torch op on tt tensors |
| `kk.Program`, `kk.CB`, `kk.Kernel` | circular buffers, the three kernels with their arguments and compute options, the outputs |
| `kk.empty`, `kk.empty_like`, `kk.split_tiles`, `kk.tile_count` | outputs; the tiles of a tensor split over the grid |
| `ktt::extension::register_program`, `KTT_REGISTER_PROGRAM` | a C++ builder `ProgramDescriptor(const std::vector<ttnn::Tensor>&, const Numerics&)` with optional `Requirements` |
| `ktt::extension::run` | runs a registered program over tt tensors from a C++ op |
| `kohakutt.extension.load`, `cmake_module`, `include_dir` | loads an extension library; paths for its build |

## Measured

Device-synchronized time per call over 20 async calls: a SwiGLU written this way runs in
0.132 ms against 0.283 ms for `F.silu(a) * b` at 1024 x 4096 bf16, and a RoPE rotation
written in SFPU instructions in 0.113 ms against 0.325 ms for the cast, complex multiply
and cast it replaces ([measured](measured.md#kernels)).
